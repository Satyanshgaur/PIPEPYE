Architecture · End-to-End Pipeline

Master Pipeline Architecture

PipePye enforces a strict architectural boundary separating problem ingestion and transformation from numerical execution and solution verification.

Solvers do not ingest raw file streams or mutate client problem representations. Instead, optimization workloads transition through a unidirectional pipeline:

System Invariant: The PreparedLP Boundary

All numerical solvers operate exclusively upon an immutable PreparedLP structure in bounded canonical format: $$\min_{x} c^T x \quad \text{subject to} \quad l_r \le Ax \le u_r, \quad l_c \le x \le u_c$$ Solvers do not access raw file paths, do not implement model scaling, and do not perform postsolve expansions. When a solver reaches termination, its solution vector $x'$ is transformed back to original coordinates via the exact mathematical inverse operations recorded in the LIFO postsolve stack.

SpMV Kernel Topology Matching

Four distinct CUDA CSR SpMV kernel architectures were engineered and benchmarked against matrix row-degree variance:

  • Scalar Kernel (1 Thread / Row): Maximizes occupancy for short, uniform rows where warp divergence is zero. Achieved 133.44 GB/s on uniform random matrices.
  • Vector Kernel (1 Warp / Row): 32 threads collaborate on a single row using warp-shuffle reductions. Highly effective on wide rows (achieved 66.01 GB/s on block-diagonal systems).
  • Adaptive Sub-Warp Kernel (8 Threads / Row): Splits 32-thread warps into four 8-thread cooperative groups. Delivered optimal efficiency on banded (141.63 GB/s) and scale-free hub rows (119.21 GB/s).
  • Balanced Kernel (Work-Partitioned): Partitions nonzeros evenly across thread blocks with row mapping arrays, avoiding tail stragglers on power-law matrices.

Research Finding: The VRAM Residency Requirement

Host-to-Device PCIe transfer bandwidth was measured at $5.43\text{ GB/s}$, requiring approximately $150\,\mu\text{s}$ to transfer state vectors for a $10^5$-dimension problem. In contrast, the GPU SpMV kernel executed in $20\,\mu\text{s}$. Transferring iterate vectors across the PCIe bus on every iteration would cause PCIe latency to constitute $>95\%$ of runtime. Therefore, complete iterate residency in VRAM is mandatory for first-order GPU solvers.

Phase 2 · Model Preparation

Modular Presolve, Ruiz Scaling & Structural Analysis

Raw mathematical programming formulations frequently contain pathological numerical conditioning, redundant constraints, and unconstrained variables that degrade solver convergence.

Five Presolve Reduction Passes

PipePye executes five idempotent reduction passes with provable mathematical invariants:

  1. Empty Row & Column Elimination: Removes rows with zero nonzeros (detecting infeasibility if $b_i \neq 0$) and unconstrained columns (detecting unboundedness if $c_j \neq 0$).
  2. Fixed Variable Elimination: Detects variables where $l_j = u_j = \hat{x}_j$. Substitutes $\hat{x}_j$ into active rows: $b'_i = b_i - A_{i,j} \hat{x}_j$, shifts objective constant $c_0' = c_0 + c_j \hat{x}_j$, and pushes fixed coordinates to the postsolve stack.
  3. Singleton Row & Column Reductions: Solves rows containing exactly one non-zero coefficient $A_{i,k} x_k = b_i$ directly, propagating exact bounds to $x_k$.
  4. Forcing & Redundant Row Pruning: Computes interval activity bounds $[L_i, U_i] = [\sum \min(A_{ij} l_j, A_{ij} u_j), \sum \max(A_{ij} l_j, A_{ij} u_j)]$. If $U_i \le u_i$ and $L_i \ge l_i$, the constraint is redundant and pruned. If $L_i = u_i$, all participating variables are forced to their bound extremes.
  5. Activity Bound Tightening: Propagates row bounds back to variable bounds: $x_j \le (u_i - L_{i,-j}) / A_{i,j}$.

Reversible Postsolve Reconstruction Stack

Every reduction pass pushes its exact inverse algebraic operation onto a Last-In, First-Out (LIFO) postsolve stack. Once the solver returns an optimal solution on the reduced space, the postsolve engine unwinds the stack:

Ruiz Equilibration & Conditioning Compression

PipePye applies the iterative Ruiz equilibration algorithm to find diagonal scaling matrices $R \in \mathbb{R}^{m \times m}$ and $C \in \mathbb{R}^{n \times n}$ such that: $$A' = R A C, \quad b' = R b, \quad c' = C c$$ where row and column $L_\infty$ norms asymptotically converge to 1. On standard Netlib problems, Ruiz equilibration converged in 10 to 16 iterations, compressing dynamic ranges by up to three orders of magnitude.

Phase 3 · First-Order Optimization

Primal-Dual Hybrid Gradient (PDHG) GPU Solver

Phase 3 established the first complete optimization solver path in PipePye: a Chambolle-Pock first-order saddle-point algorithm designed specifically for fine-grained parallel execution on CUDA GPUs.

Mathematical Formulation

The canonical bounded LP is cast as a saddle-point minimax problem: $$\min_{x \in [l_c, u_c]} \max_{y \in \mathcal{Y}} \left( c^T x + y^T (Ax) - \delta_{[l_r, u_r]}^*(y) \right)$$ The PDHG algorithm iteratively executes proximal gradient steps:

Chambolle-Pock Iteration Equations $$x^{k+1} = \mathrm{proj}_{[l_c, u_c]} \left( x^k - \tau \left( c + A^T y^k \right) \right)$$ $$\bar{x}^{k+1} = 2 x^{k+1} - x^k \quad (\text{Primal Extrapolation})$$ $$y^{k+1} = \mathrm{prox}_{\sigma g^*} \left( y^k + \sigma A \bar{x}^{k+1} \right)$$

The dual proximal operator is evaluated in closed form using Moreau's identity: $$\mathrm{prox}_{\sigma g^*}(v) = v - \sigma \cdot \mathrm{proj}_{[l_r, u_r]}\left(\frac{v}{\sigma}\right)$$

Pock-Chambolle Diagonal Preconditioning

Rather than using scalar steps $\tau, \sigma$ bounded by $1 / \|A\|_2$, PipePye implements coordinate-wise diagonal preconditioning: $$\tau_j = \frac{1}{\sum_{i=1}^m |A_{ij}|^\alpha}, \quad \sigma_i = \frac{1}{\sum_{j=1}^n |A_{ij}|^{2-\alpha}} \quad (\text{with } \alpha = 1.0)$$ On a 1,000 × 1,000 synthetic test polytope, Pock-Chambolle preconditioning reduced the primal infeasibility residual from $3.00 \times 10^{-3}$ to $9.50 \times 10^{-6}$ (over 300× reduction) under identical iteration limits.

Phase 4 · Active-Set Optimization

Sparse Dual Revised Simplex Engine

Phase 4 established the second major optimization path in PipePye: a high-precision sparse Dual Revised Simplex solver with Markowitz LU factorization, Product Form of the Inverse (PFI) updates, and Devex pricing.

While first-order methods excel at parallel matrix-vector operations, they exhibit asymptotic deceleration near degenerate polyhedral vertices. The Dual Revised Simplex algorithm navigates directly along basic feasible extreme points, guaranteeing finite termination to exact machine precision.

Algorithmic Components

  • Markowitz Threshold Factorization ($u=0.1$): Selects pivot elements balancing structural sparsity (minimizing fill-in) with numerical stability: $|A_{p,q}| \ge u \cdot \max_i |A_{i,q}|$. Achieved a 1.000 fill-in ratio on banded test systems.
  • Product Form of the Inverse (PFI): Replaces expensive basis reinversions with elementary eta matrices $B_{k+1}^{-1} = E_k B_k^{-1}$, accumulating eta vectors until threshold limits trigger refactorization.
  • Devex Pricing in Normalized Dual Space: Approximates steepest-edge norms without the cost of full vector solves, selecting pivots that prevent zig-zagging in degenerate bases.
  • Bound-Flipping Ratio Test: Accelerates dual pivots by passing through multiple non-basic bounds in a single iteration when dual feasibility is preserved.

Hybrid Algorithm: PDHG to Simplex Basis Crossover

To combine the throughput of GPU first-order iterations with the precision of vertex bases, PipePye implements a three-stage basis crossover mechanism:

  1. Active Set Identification: Examines iterate vector $x^*$ from PDHG; variables within tolerance $|x_j^* - l_j| \le \epsilon_{\text{cross}}$ are assigned to their active bounds.
  2. Basis Crash & Triangularization: Constructs a structurally nonsingular basis matrix $B$ from non-active candidate columns.
  3. Dual Simplex Cleanup: Initiates dual simplex from the crashed basis, executing clean-up pivots (typically < 5% of cold start pivots) to reach exact vertex optimality.

MILP Dynamics · Mathematical Verification

Branch-and-Bound & Simplex Warm-Start Dynamics

Evaluating mixed-integer programming instances demonstrated the decisive role of Dual Simplex warm-starting when solving sequences of related subproblems during tree search.

Mathematical Invariant: Dual Feasibility Preservation Under Bound Branching

When branching on a fractional binary variable $x_j^* \in (0, 1)$ creates child problems with restricted bounds: $$\text{Left Child: } x_j \le 0 \quad \text{or} \quad \text{Right Child: } x_j \ge 1$$ in the Dual Revised Simplex representation, tightening the bounds of variable $j$:

  1. Leaves the reduced cost condition $d_N = c_N - A_N^T y \ge 0$ completely unchanged for all non-basic columns.
  2. Leaves the inverse basis representation $B^{-1}$ algebraically identical.
  3. Introduces primal infeasibility exclusively on the branched coordinate if forced off bound.

Consequently, the optimal basis from the parent node is immediately dual-feasible for the child subproblem. Dual Simplex re-optimizes from this advanced basis, restoring primal feasibility in a tiny number of dual ratio pivots.

Empirical Scrutiny · Boundary Analysis

Negative Results & Boundary Limitations

Rigorous scientific evaluation requires documenting where algorithmic strategies fail or encounter severe computational penalties.

1. The GPU Penalty on Small / Dense Topologies

On BLENDING_Small ($m=26, n=18$, density $30.1\%$), GPU PDHG took 236.19 ms, while CPU Dual Simplex terminated in < 0.01 ms and CPU PDHG took 2.16 ms. Allocating CUDA streams, binding device buffers, and synchronizing device state incurred orders of magnitude more overhead than the arithmetic content of 141 floating-point operations.

2. Asymptotic Stalling of First-Order Solvers

On degenerate problems such as Netlib BLEND, PDHG consumed 20,000 iterations (the maximum iteration budget) without reaching $10^{-4}$ tolerance, terminating with a primal infeasibility of $3.94 \times 10^{-2}$. Dual Revised Simplex resolved the identical model to exact vertex optimality in 136 pivots. First-order methods are ill-suited for degenerate polyhedra without active-set crossover.

3. Cold-Start Simplex Combinatorial Explosion

Attempting to evaluate Branch-and-Bound tree nodes using cold-start simplex leads to explosive scaling. In UNIT_COMMIT_Medium, cold simplex required 110,541 pivots across 500 nodes, exhausting memory and CPU time, whereas warm-starting completed the exact same tree in 4,209 pivots.
